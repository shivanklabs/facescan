# FaceScan Disaster Recovery & Restore Runbook

This runbook documents the exact, reproducible procedure to restore FaceScan on a fresh machine from an atomic backup directory generated by `uv run tasks backup`.

---

## 1. Prerequisites on the Fresh Machine

1. **System & Tooling**:
   - Python 3.12+ and `uv` package manager (`winget install astral-sh.uv` or curl installer).
   - Node.js 20+ and npm (`winget install OpenJS.NodeJS.LTS`).
   - PostgreSQL 15+ (native server running on default port or custom port).
   - PostgreSQL client utilities (`pg_restore`, `psql`) installed and available in `PATH` or configured via `FACESCAN_DB_PSQL_DIR`.

2. **Source Code**:
   - Clone the repository to the new machine:
     ```bash
     git clone <repo-url> facescan
     cd facescan
     ```

3. **Backup Directory**:
   - Copy or download the backup directory (e.g., `backup_20261111_120000Z`) to the fresh host.
   - Verify that `manifest.json`, `database.dump`, and `storage/` exist in the backup directory.

---

## 2. Restore Procedure (Step-by-Step)

### Step 2.1: Verify Backup Manifest Before Restoring
Verify the integrity of all files in the backup directory against `manifest.json`:
```bash
python -c "
import json, hashlib, sys
from pathlib import Path

backup_dir = Path('<PATH_TO_BACKUP_DIR>')
manifest = json.loads((backup_dir / 'manifest.json').read_text(encoding='utf-8'))
for item in manifest['files']:
    p = backup_dir / item['path']
    if not p.is_file():
        sys.exit(f'Missing file: {item[\"path\"]}')
    h = hashlib.sha256()
    with open(p, 'rb') as f:
        while chunk := f.read(65536):
            h.update(chunk)
    if h.hexdigest() != item['sha256']:
        sys.exit(f'Checksum mismatch on: {item[\"path\"]}')
print(f'Integrity verified: all {manifest[\"file_count\"]} files match manifest.')
"
```

### Step 2.2: Setup Environment and Secrets (.env)
1. Initialize development/production environment configuration:
   ```bash
   uv run tasks setup
   ```
2. Open `.env` and set:
   - `FACESCAN_DB_USER`, `FACESCAN_DB_PASSWORD`, `FACESCAN_DB_PORT`, `FACESCAN_DB_NAME`, and `FACESCAN_DB_URL`.
   - **CRITICAL**: Set `FACESCAN_KEYS_MASTER_KEY` to the **original master key** used by the backed-up instance. Per-event AES-256 keys in the database are encrypted under this master key; without the matching master key, photo and face data cannot be decrypted.
   - Set `FACESCAN_STORAGE_SIGNING_KEY` to the original signing key if existing signed download URLs need to be honored, or a fresh secret.

### Step 2.3: Initialize Fresh Database Role and Schema
1. Create the `facescan` database role and blank database:
   ```bash
   uv run tasks db-init
   ```

### Step 2.4: Restore PostgreSQL Database from Dump
Restore the database schema and all table data using `pg_restore`:
```bash
# If using clean URL (replace credentials accordingly):
pg_restore --clean --if-exists --no-owner --no-privileges -d "<FACESCAN_DB_URL>" "<PATH_TO_BACKUP_DIR>/database.dump"
```
*Note: `--clean --if-exists` drops existing objects before recreating them; `--no-owner` ensures restored objects are owned by the active connecting role.*

### Step 2.5: Restore Photo Storage Directory
Copy the storage directory from the backup into the configured storage root:
```bash
# Example assuming default storage root var/storage:
mkdir -p var/storage
cp -r "<PATH_TO_BACKUP_DIR>/storage/"* var/storage/
# On Windows PowerShell:
# Copy-Item -Recurse -Force "<PATH_TO_BACKUP_DIR>\storage\*" var\storage\
```

### Step 2.6: Migration Check
Run migrations to ensure Alembic is synchronized at the expected revision:
```bash
uv run tasks db-migrate
```

### Step 2.7: Verification & Health Check
1. Run automated test suite to verify application logic and database connectivity:
   ```bash
   uv run tasks test
   ```
2. Start the application stack:
   ```bash
   uv run tasks dev
   ```
   Or for production / phone test mode:
   ```bash
   uv run tasks public
   ```
3. Log in as organiser, check that events, collections, and guest galleries display restored photos accurately.
